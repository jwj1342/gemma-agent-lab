# Data description and usage

The complete official text is preserved in [data-description.md](../resource/competition/data-description.md).
This guide interprets the verified local inventory without modifying the original package.

## Inventory

| File or directory | Count | Purpose |
| --- | ---: | --- |
| `tasks.jsonl` | 129 rows | Issues, repository revisions, reference repairs, and tests |
| `snapshots/` | 129 TGZ files | Git snapshots with future repair history removed |
| `graphs/` | 127 JSON files | Symbol graphs for unique repository/base-commit pairs |
| `embeddings/` | 127 NPZ files | 256-dimensional float32 vectors for graph nodes |
| `wheels/` | 124 wheels | Repository-test dependencies, separate from the vLLM/ADK runtime |
| `docker/` | 4 files | Python 3.13 sandbox specification and compatibility shim |
| `sandbox/setup.py` | 1 file | Repository/test setup, executed only inside the sandbox |
| `sample_submission/` | 10 files | Official YAML, prompts, and two example LoRA adapters |
| `HARNESS_README.md` | 1 file | Complete technical manual |

The package contains 524 files totaling 20.88 GiB; its ZIP is 20.42 GiB. Extracting every repository
would add about 21.13 GiB and 238,000 entries, so extract on demand. The description's older count
of 256 graph/embedding files included task-name hardlinks. The current package has 127 commit-name
files of each kind; all 129 tasks match, with no missing assets in the audited inventory.

## Task fields

| Field | Meaning | Boundary |
| --- | --- | --- |
| `instance_id` | Unique identifier such as `rich_3454` | Joins outputs, traces, and patches |
| `repo` | `owner/repo` | Handle the slash explicitly when constructing paths |
| `base_commit` | Revision before repair | Groups splits and matches snapshots, graphs, and embeddings |
| `problem_statement` | Issue text | Inference input |
| `hints_text` | Optional maintainer hints | Expose according to the harness protocol |
| `patch` | Reference repair diff | Training label or gold verification; excluded from evaluation inputs |
| `test_patch` | Validation-test diff | Isolated scoring evidence; hidden during official evaluation |
| `created_at` | Issue timestamp | Distribution and split analysis |

Public tasks: FastAPI 67, Rich 48, Requests 13, HTTPX 1. Group training/validation by repository
and base commit so the same repository snapshot cannot appear on both sides of a random row split.

## Graphs and embeddings

Graphs are directed multigraphs. Nodes contain `id`, `name`, and `text`; edges contain `source`,
`target`, `type`, and `key`. The 127 audited graphs contain only `calls` edges. Other relationships
shown as documentation examples do not prove their presence in this dataset. Each `<node_id>.npy`
entry in an NPZ contains a 256-element float32 vector.

Find real symbols through issue/source search before requesting neighbors, subgraphs, or similar
symbols. Known coverage issues include missing async functions; a missing node does not imply
missing source code. Verify query semantics before treating `search_similar_code` as a general
natural-language vector search service. Graphs are neither reference patches nor complete dependency maps.

## Two wheelhouses

`data/raw/.../wheels/` supports historical repository tests. The separate Kaggle dataset
`metric/gemma-4-developer-agent-wheelhouse` supplies vLLM, ADK, swegemma, and related harness packages.
Some harness binaries require Python 3.12, while the Docker test sandbox uses Python 3.13.
Install each wheel set only into its intended environment.

Public test wheels omit some task dependencies. Before using a task for rewards, establish that
the unmodified code fails and the reference patch passes. Keep dependency errors, collection failures,
and timeouts separate from repair failures. Preserve full logs and keep validation tests unchanged.
