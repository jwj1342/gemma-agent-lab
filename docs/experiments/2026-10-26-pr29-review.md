## Two remaining issues

1. **[P1] Reasoning in `content` is still discarded.**
   In `src/sft_data.py:115-123`, `assistant_reasoning()` reads only `reasoning`
   and `reasoning_content`. For native tool-call messages with explicit reasoning
   in `content`, enabling `--preserve-reasoning` produces the same actions-only
   output as disabling it. Independently reproduced with a synthetic row matching
   the shape reported by jwj1342; this confirms the owner's existing blocker.
   Support content alongside native calls under the opt-in policy, define field
   precedence, and add a representative regression test. XML parsing can follow separately.

2. **[P2] Mixed diffs can produce incomplete file membership.**
   In `src/failure_mechanisms.py:165-170`, a standalone pure rename returns unknown,
   but adding a normal text hunk makes the parser return only the text file.
   Reproduced with a real Git diff modifying `notes.txt` and renaming
   `pkg/old.py` to `pkg/new.py`: `prediction_paths()` returns `['notes.txt']`.
   If `pkg/old.py` is a reference file, `final_patch_reference` becomes `False`
   despite the rename affecting it. Return unknown when any file section is
   unsupported, or parse all affected paths; add mixed-section regression tests.
   No impact on published r4/r5 counts has been established.
