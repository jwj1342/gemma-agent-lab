# Wheelhouse version 31 on H100: baseline, protocol and recover

## Question and comparison

- Hypothesis: the `recover` prompt from [#22](https://github.com/jwj1342/gemma-agent-lab/pull/22) reduces
  malformed editor calls and wasted retries compared with `protocol`. Its Kaggle smoke changed the
  prompt and the official wheelhouse at the same time, so the effect could not be attributed. This run
  compares the three prompts inside one recorded environment.
- Baseline and proposed change: `configs/baseline`, then `protocol` and `recover` built with
  `scripts/build_prompt_candidate.py`. Same model, tools, sampling, budget and task order.
- Task IDs / grouped split and data version: the frozen `fast` cohort of
  `configs/evaluation/public-v1.json` (12 tasks). Competition data re-published on 2026-10-13 differs
  from the local copy only in `HARNESS_README.md`; tasks, snapshots, graphs, embeddings and test wheels
  are byte-identical.
- Success metric: resolved tasks among tasks with valid empty/gold controls; trace-audit tool errors.

## Results

- Original-failure and reference-success controls: 10/12 valid in every variant.
  `fastapi_15745` was already invalid on version 29. `requests_7502` was valid on version 29, but its
  gold patch now fails two TLS connection-pool tests (`Connection refused` from the local test
  server). This looks like a flaky local server rather than a harness change, but it is not confirmed.
- Pipeline execution / issue resolution:

  | Variant | Resolved | Clean completions | Tool errors | Missing-argument events | Longest error streak |
  | --- | ---: | ---: | ---: | ---: | ---: |
  | baseline | 1/10 | 7 | 43 | 0 | 3 |
  | protocol | 2/10 | 7 | 50 | 22 | 5 |
  | recover | 3/10 | 6 | 68 | 15 | 3 |

  Resolved tasks: baseline `httpx_3672`; protocol adds `rich_3278`; recover adds `rich_3278` and
  `fastapi_9753`. No task resolved by baseline or protocol was lost by recover.
- Model startup, agent time, total elapsed time, and quota used: one startup per variant
  (260–275 s); runner time 3,916–4,269 s; 3.40 physical H100 hours in total. No Kaggle quota used.
- Measured metrics, failure stages, and limitations: one attempt per task on 10 tasks, so a
  two-task difference is within noise. Baseline had no missing-argument events on version 31, while
  both prompt variants that mention the editor's arguments did, so the version-29 corruption pattern
  does not carry over unchanged.
- Comparison with the baseline on matching tasks: on version 29 the same baseline and protocol
  agents each resolved 2/11 (`httpx_3672`, `requests_7502`). Results from the two environments are
  not directly comparable.
