# Mined-cohort evaluation protocol and the first arm specification (2026-11-21)

Purpose: use the frozen mined cohort to resolve one- and two-task differences that the 29-task competition
cohort cannot resolve. This is the "larger local evaluation set" deliverable of #34; the cohort, the control
gate and the cost model are already measured (see `2026-11-20-mined-task-evaluation-tooling.md`).

## Cohort

- File: `scripts/select_mined_cohort.py` output, seed `mined-cohort-2026-11-21`, **105 tasks**. Deterministic:
  terse statements first, then ascending SHA-256 rank, proportional per-repository quotas.
- Composition: click 34, tomlkit 26, mobly 20, lark 8, sqlparse 7, arrow 6, ml_collections 4; statement types
  terse 23 / concrete 73 / design 9; leak-flagged 35 / clean 70 (reported as strata, never filtered).
- Provenance of validity: 226 of the 297 holdout tasks passed the gold/empty control gate in CPU kernels
  (`junzhejiao/mined-control-sweep-2026-11-20` v2 plus `junzhejiao/mined-control-residual-2026-11-20`);
  openhtf (24) and humanize (23) are written off in #34.
- Snapshots: `<instance_id>.tgz` with repository content at the archive root, confirmed against swegemma
  0.2.11, built by `scripts/build_mined_eval_bundle.py`; wheels are cp312 manylinux from PyPI.

## Arm definition

| Field | Value |
| --- | --- |
| Control | frozen `kaggle-l4-r5/c2/agent` (prompt `454defe0...`, bundle `68079929...`) |
| Candidate (first use) | the #29 observation-checkpoint paragraph, candidate commit `cad2d66f` |
| Only difference | `prompts/system.md` (the registered paragraph swap) |
| Budget | **8 min, 28 tool calls, 240 s command timeout, 80 turns** (submission parity) |
| Sampling | server seed 42; seed label 42 omits the sampling seed, labels 1/2/3 set it in both arms |
| Model | `gemma-4-31b-it-qat-w4a16-ct`, no adapter |
| Hardware | H100 queue; TP 1, memory 0.8, 32 K context, concurrency 1 |

**Do not use a 4-minute budget.** The r5 failures averaged 348 s of agent time at 8 minutes, and every repair
arm we ran at 4 minutes timed out before submitting. The 0.5 time scaling in #29's protocol is the one thing
this cohort cannot absorb.

## Analysis plan (pre-registered)

- **Primary**: paired resolution over the 105 tasks, exact McNemar, reported per repository and pooled.
  Success = the paired 95 % interval excludes zero **and** the non-inferiority margin of −3.45 points
  (the margin #29 registered) is cleared.
- **Secondary**: empty-patch rate, clean nonempty completions, session timeouts, tool-call-budget endings,
  median agent time, first accepted edit call.
- **Stratification**: repository, statement type, leak flag; report each stratum's N and rate rather than
  weighting them.
- **Bootstrap**: task-cluster bootstrap (10,000 resamples, tasks clustered, seeds kept together), matching the
  #29 analysis so the two cohorts are comparable.
- **Failure policy**: a task whose control fails is excluded before inference and reported; no re-draw after
  results are seen.

## Cost

At the measured per-task cost (323.7-361.5 s of agent time + 60 s of verification + 1,827 s setup; 2x billing
on 4xL4) a 105-task arm is about **42-45k quota-seconds**: too large for one 4xL4 monthly allowance as a pair,
which is why this arm belongs on the H100 queue. On 4xL4 the same protocol runs at **50 tasks per arm**
(about 20-21k quota-seconds per arm, a pair fits).

## Deliverables per arm

`summary.json` (resolved, measured tasks, excluded controls), per-task CSV (task, repo, resolved, patch bytes,
tool calls, agent seconds, first edit call, error), the kernel log, and the paired analysis JSON produced by
`scripts/collect_mined_sweep.py --from-log`.
